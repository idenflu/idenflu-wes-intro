# NOVA 소개자료 콘텐츠 소스

NOVA, NOVA Workspace, NOVA Studio의 제품 설명과 브라우저 소개자료의 문구를 관리하는 단일 기준 문서다. 현재 `index.html`의 23장 구성과 제품 메시지, 기술 설명 근거, 영업 질문, 준비할 시각자료를 함께 정리한다.

- 기준일: 2026-10-28
- 주요 독자: 물류 운영 책임자, IT 관리자, 설비·자동화 담당자, 의사결정자
- 기대 행동: 현재 운영과 연동 대상을 확인하고 첫 적용 범위를 논의한다.
- 콘텐츠 변경 순서: 이 문서에서 메시지와 범위를 정리한 뒤 `index.html`에 반영한다.
- 디자인 기준: [NOVA 디자인 기준](nova-design-foundations.md), `design-system/`의 토큰과 컴포넌트
- `type0.html`부터 `type3.html` 및 기존 HTML 백업은 과거 표현 참고용이다. 현재 소개자료의 구성과 문구는 아래 23장 구성을 따른다.

## 1 제품 정의와 핵심 메시지

### 제품 한 줄 정의

> NOVA는 작업과 설비, 실시간 정보와 운영 이력을 연결하는 WES/WCS 운영 플랫폼입니다.

### 핵심 약속

> 실시간으로 보고, 안정적으로 실행하고, 유연하게 확장합니다.

| 가치 | 고객에게 설명할 내용 | 설명에 사용할 근거 |
| --- | --- | --- |
| 운영 가시성 | 작업 진행, 설비 상태, 알람과 이력을 연결해 운영 상황을 확인한다. | Workspace 현황·이력, Studio 현장 배치 |
| 안정성 | 표준화된 기반과 현장 적용 검증을 통해 안정적인 운영을 지원한다. | 작업 상태 관리, 연결 상태 확인, 권한·감사, 운영 검증 절차 |
| 확장성과 유연성 | 업무와 설비의 차이를 반영하고 검증 결과에 따라 적용 범위를 넓힌다. | WES·WCS 역할 분리, 업무·설비·화면 확장 |
| 요구사항 반영 | 업무 규칙, 설비 인터페이스와 예외 조건을 나누어 적용 범위를 정한다. | 현장 진단, 파일럿 정의, 정상·예외 시나리오 검증 |

### 솔루션의 역할 구분

| 구분 | 역할 | 주요 내용 | 관계 |
| --- | --- | --- | --- |
| NOVA | 물류 작업 실행과 설비 연동 | WES 작업 조율, WCS 설비 연동 | 실행·제어의 기반 |
| NOVA Workspace | NOVA의 운영 화면 | 현황·이력, 사용자·역할, 설정·스케줄, 운영 점검 | NOVA의 운영 데이터를 확인하고 운영 환경을 관리 |
| NOVA Studio | 현장 시각화 | 2.5D·3D 배치, 설비 상태, 알람 위치 | NOVA 또는 기존 운영 시스템의 데이터를 현장 위치에 연결 |

WES는 작업 구성·우선순위·상태·예외를 조율하고, WCS는 설비별 명령 전달과 상태 수집·연결 확인을 맡는다. Workspace의 운영 정보 조회와 Studio의 공간 시각화를 같은 기능으로 설명하지 않는다.

### 도입 방식에서의 위치

| SI 개발 | NOVA | 패키지 제품 |
| --- | --- | --- |
| 프로젝트별 설계·개발 | 표준화·검증된 플랫폼 기반 | 제품 기능에 맞춘 도입 |
| 기간·비용·안정성 확보 부담 | 현장에 맞춘 업무·설비 확장 | 업무·운영 방식을 조정하는 부담 |

> 표준화된 기반, 현장에 맞춘 확장

표준화와 검증을 바탕으로 안정적인 서비스를 제공한다는 메시지를 중심에 둔다. SI 개발과 패키지 제품을 잇는 연속선에서 NOVA의 적용 범위를 표현한다. 범위는 개념적인 위치이며, 실제 개발·설정·검증 범위는 현장 요구에 따라 달라진다.

## 2 현재 소개자료의 구성

| 섹션 | 슬라이드 | 설명 흐름 |
| --- | --- | --- |
| 소개 | 01 | NOVA의 정의와 약속 |
| 물류자동화 | 02–04 | 시스템 개요 → 주요 업무 → 특징 |
| 솔루션 | 05–17 | 포지셔닝 → 솔루션 관계 → NOVA → Workspace → Studio → 적용 구성 |
| 운영과 확장 | 18–20 | 운영 기준 → 확장 범위 → 플랫폼 구조 |
| 도입 | 21–23 | 도입 방식 → 도입사례 → 다음 단계 |

별도의 ‘문제’ 슬라이드는 현재 구성에서 제외한다. 문제 상황과 고객 질문은 영업 설명의 배경으로 활용한다. 포지셔닝을 솔루션 구성보다 먼저 설명하고, 기술 구조는 제품 역할을 이해한 뒤 제시한다.

### 01 NOVA 소개

- 상단 문구: 물류 운영의 새로운 기준
- 제목: **흩어진 물류 운영을 하나의 기준으로.**
- 설명: NOVA는 작업과 설비, 실시간 정보와 운영 이력을 연결하는 WES/WCS 운영 플랫폼입니다.
- 하단 문구: 실시간으로 보고, 안정적으로 실행하고, 유연하게 확장합니다.
- 표현: 제품명과 한 줄 정의를 중심으로 시작한다.

### 02 물류자동화 개요

- 제목: **업무 요청에서 현장 실행까지**
- 설명: 시스템의 요청을 작업과 설비 명령으로 연결하고, 실행 결과를 다시 운영에 반영합니다.
- 흐름: 업무 시스템 → 실행·제어 → 자동화 설비
- 업무 시스템: 주문·재고·생산 / ERP·WMS·MES
- 실행·제어: 작업 조율·설비 연동
- 자동화 설비: 보관·이송·분류 / ASRS·AGV/AMR·컨베이어
- 결과 회수: 진행·완료·알람을 다시 운영에 반영
- 조건: 실제 연계 대상과 구성은 현장 조건에 따라 달라집니다.

### 03 물류자동화 주요 업무

- 상단 문구: 요청부터 확인까지
- 제목: **작업을 실행하고, 설비를 연결하고, 운영을 확인합니다.**
- 설명: 현장 업무와 설비 조건을 함께 살펴 필요한 실행·제어 범위를 정합니다.
- 작업 실행 관리: 요청을 작업으로 구성하고 순서와 진행 상태를 관리합니다.
- 설비 연동·제어: 설비별 명령을 전달하고 진행·완료·알람을 수집합니다.
- 운영 현황과 이력: 작업과 설비 상태, 알람과 운영 이력을 확인합니다.

### 04 물류자동화 특징

- 상단 문구: 일관된 기준 위에 현장의 차이를 반영
- 제목: **연결하고, 확인하고, 현장에 맞춰 확장합니다.**
- 설명: 공통 운영 기준을 바탕으로 시스템과 설비를 연결하고, 실제 업무 조건에 맞게 적용 범위를 설계합니다.
- 연결된 실행: 상위 시스템의 요청과 설비의 실행 결과를 같은 흐름으로 이어갑니다.
- 운영 가시성: 작업 진행, 설비 상태와 알람을 확인할 수 있도록 정보를 연결합니다.
- 현장 맞춤 확장: 업무 규칙과 설비 인터페이스를 확인해 필요한 구간부터 구성합니다.

### 05 NOVA 포지셔닝

- 제목: **표준화된 기반, 현장에 맞춘 확장**
- 설명: 표준화와 검증을 바탕으로 안정적인 서비스를 제공합니다.
- 비교 문구: 1절 ‘도입 방식에서의 위치’ 표를 사용한다.
- 표현: SI 개발은 왼쪽, NOVA는 가운데, 패키지 제품은 오른쪽에 둔다. 항목명은 범위선 위, 설명은 아래에 배치한다.
- 도식: 가는 기준선 위에 양끝 화살촉이 있는 NOVA 범위를 강조한다. 원으로 특정 지점을 찍거나 세 개의 독립된 막대로 분리하지 않는다.
- ‘장점·고려할 점’ 구분, ‘NOVA 적용 범위’ 라벨, 중복되는 하단 요약은 넣지 않는다.
- 조건: 개념적 위치이며, 개발과 설정 범위는 현장 요구에 따라 달라집니다.

### 06 솔루션 구성

- 제목: **실행·운영·시각화의 연결**
- 설명: NOVA의 실행 데이터를 운영 화면과 현장 시각화에 연결합니다.
- NOVA: WES·작업 조율 / WCS·설비 연동
- NOVA Workspace: NOVA의 운영 화면 / 현황·이력·사용자·설정
- NOVA Studio: 현장 시각화 / 2.5D·3D 현장 배치·상태·알람
- 도식: 아래의 NOVA에서 위의 Workspace와 Studio로 분기한다. 연결선 위의 ‘운영 데이터’ 문구는 생략한다.
- 조건: Workspace는 NOVA의 운영 화면이며, Studio는 NOVA 또는 기존 시스템과 연계합니다.

### 07 NOVA 실행과 제어

- 제목: **작업 순서를 설비 실행으로**
- 설명: WES가 실행할 작업을 조율하고, WCS가 설비별 명령 전달과 상태 수집을 맡습니다.
- 흐름: 상위 시스템 → 작업 요청 → NOVA의 WES → 작업 지시 → NOVA의 WCS → 설비 명령 → 설비
- 상위 시스템: ERP·WMS·MES
- WES의 역할: 작업 조율 / 작업 구성, 우선순위·예외 관리
- WCS의 역할: 설비 연동 / 명령 변환, 상태 수집·연결 확인
- 설비의 역할: 지시 실행 / 진행·완료·알람
- 결과 회수: 설비 상태·실행 결과를 회수해 다음 작업에 반영
- 표현: NOVA 공통 헤더 아래에 WES·WCS를 하위 기능으로 묶는다. 상위 시스템과 설비는 NOVA 바깥에 둔다.
- 연동 설비 예시: ASRS / AGV·AMR / 컨베이어 / 소터

### 08 WES 상세

- 제목: **작업 구성과 실행 순서 관리**
- 작업 구성: 상위 요청을 현장에서 처리할 작업으로 나눕니다.
- 순서 조정: 우선순위와 현장 상황에 맞춰 대기 작업을 정렬합니다.
- 상태 관리: 진행·완료·예외를 확인해 후속 실행에 반영합니다.
- 도식: 대기 → 진행 → 완료, 예외는 현장 기준에 따라 확인한다.
- 조건: 상태와 전이 기준은 적용 업무에 맞춰 정합니다.

### 09 WCS 상세

- 제목: **설비 명령과 실행 결과 연결**
- 설비 연결: 장비별 통신 방식과 명령·상태 정보를 연결합니다.
- 명령·결과 처리: 작업 지시를 변환하고 실행 상태를 수집합니다.
- 연결 상태 확인: 통신 단절과 응답 지연을 확인합니다.
- 도식: 작업 지시는 WES → WCS → 설비, 상태·결과는 설비 → WCS → WES로 연결한다.
- 조건: 제어 범위와 프로토콜은 설비 사양을 확인해 정합니다.

### 10 출고 시나리오

- 제목: **급한 출고 요청이 들어오면**
- 설명: 우선순위와 현장 상태를 반영해 대기 작업의 실행 순서를 조정합니다.
- 변경 전: 일반 출고가 먼저 대기하고, 우선 출고가 뒤에 있다.
- 조정 후: 변경된 우선순위에 따라 우선 출고를 앞에 배치한다.
- 흐름: WMS 요청 → WES 순서 조정 → WCS 실행 → 진행·결과 확인
- 조건: 기능 이해를 위한 예시입니다. 작업 순서와 적용 규칙은 현장 조건에 따라 달라집니다.

### 11 NOVA Workspace

- 상단 문구: 같은 출고 작업 / 운영 확인
- 제목: **출고 작업의 진행과 결과를 확인합니다**
- 설명: NOVA Workspace에서 출고 작업의 진행과 설비 상태, 알람·이력을 확인하고 운영 환경을 관리합니다.
- 진행 확인: 대기·진행·완료 상태와 설비 현황
- 예외 추적: 알람 발생 시각과 복구 상태 조회
- 운영 환경: 사용자·권한·설정·스케줄 관리
- 시각자료 01: 출고 작업 현황 화면 / 운영 요약·작업 상태와 알람·이력 조회
- 조건: 화면 구성과 표시 항목은 적용 범위에 따라 달라질 수 있습니다.

### 12 Workspace 현황과 이력

- 제목: **작업 현황과 이력을 한곳에서**
- 운영 요약: 주요 지표와 처리 추이로 현황을 살펴봅니다.
- 작업·설비 조회: 작업 진행과 설비 사용 현황을 확인합니다.
- 알람·이력 조회: 발생 시각과 이상 내용, 복구 상태를 확인합니다.
- 시각자료 02: 현황·이력 화면 / 작업 진행, 설비 현황과 알람 목록을 설명할 화면
- 조건: 표시 항목은 적용 업무와 데이터 연계 범위에 맞춰 정합니다.

### 13 Workspace 운영 관리

- 제목: **사용자와 운영 환경 관리**
- 사용자·역할: 업무별 권한과 접근할 메뉴를 설정합니다.
- 설정·스케줄: 환경 설정과 정기 작업의 일정을 관리합니다.
- 운영 점검: 일일 집계와 서버 상태를 확인합니다.
- 시각자료 03: 권한·운영 설정 화면 / 사용자·역할 또는 설정·스케줄 화면의 주요 항목
- 조건: 메뉴와 권한의 구성은 담당 업무에 맞춰 정합니다.

### 14 NOVA Studio

## 3 제품 설명을 보강할 기술 근거

이 절은 기술 설계 관점의 설명 자료다. 제공 기능과 지원 범위는 실제 적용 버전·현장 인터페이스와 맞춰 확정한다.

### 책임을 나누는 구조

| 영역 | 책임 | 상세 설명에 사용할 내용 |
| --- | --- | --- |
| Platform | 반복되는 운영 기능의 표준화 | 인증·권한, 감사, 알림, 실시간 상태, 설정, 스케줄링 |
| Operation | 업무 규칙과 상태의 소유 | 입고·출고·이동·피킹·분류의 작업 상태, 완료 기준, 업무 예외 |
| Agent | 설비와 외부 시스템의 연결 | 명령·상태 정보 변환, 연결 상태 확인, 설비별 인터페이스 |
| Orchestration | 여러 업무와 설비가 참여하는 흐름 | 호출 순서, 타임아웃, 재시도, 보상, 수동 개입 지점 |

설계 설명은 모듈러 모놀리식, 클린 아키텍처, DDD와 모듈 경계를 기준으로 한다. BC는 책임과 데이터 소유권의 단위이며, 모듈 간 연결은 계약을 기준으로 설명한다. 모듈 분리가 곧 독립 배포, 장애 완전 격리 또는 무중단 운영을 보장한다는 뜻으로 확장하지 않는다.

### Platform의 여섯 기능

| 기능 | 고객에게 설명할 표현 | 기술 설명의 확인 항목 |
| --- | --- | --- |
| IAM | 사용자·역할·권한으로 운영 접근을 관리한다. | 인증 방식, 역할·권한 모델, 메뉴 접근 범위 |
| Audit | 설정 변경과 운영 조치의 이력을 추적한다. | 변경 전후 값, 사용자·시각, 상관관계 식별 정보, 조회·내보내기 범위 |
| Notification | 작업·설비·운영 이벤트를 필요한 대상에게 전달한다. | 지원 채널, 전달 상태, 담당·심각도 기준 |
| Realtime | 운영 화면과 현장 상태를 동기화한다. | 초기 상태 수신과 변경 데이터 전달, 갱신 주기, 연결 복구 |
| Configuration | 환경과 현장별 운영 설정을 관리한다. | 설정 소유 범위, 검증, 변경 이력 |
| Scheduling | 반복·예약 작업의 실행 일정을 관리한다. | 실행 기준, 이력, 실패 처리와 재시도 정책 |

Realtime의 설계 용어는 `snapshot-first, delta push`다. 기술 스택 설명에는 `C#`, `.NET`, `ASP.NET Core`, `EF Core`를 설계 기준으로 활용한다. 데이터베이스·인증 방식·실시간 전송·이벤트 버스·외부 프로토콜은 적용 버전의 설계와 구현을 확인한 뒤 명시한다.

### 발표용 짧은 소개

**10초 문안**

NOVA는 작업과 설비, 실시간 정보와 운영 이력을 연결하는 WES/WCS 운영 플랫폼입니다.

**30초 문안**

NOVA는 WES의 작업 조율과 WCS의 설비 연동을 표준화된 플랫폼에 연결합니다. Workspace에서 작업·설비·알람·이력을 확인하고, Studio에서 같은 정보를 현장 배치와 함께 살펴봅니다. 현장의 업무와 설비 조건을 반영하고, 필요한 구간부터 검증하며 확장합니다.

**60초 문안**

SI 개발은 프로젝트별 설계·개발에 따른 기간·비용·안정성 확보 부담이 있고, 패키지 제품은 제품의 기능에 맞춰 업무와 운영 방식을 조정해야 하는 부담이 있습니다. NOVA는 표준화·검증된 기반에 현장별 업무와 설비의 차이를 반영하는 WES/WCS 운영 플랫폼입니다. WES가 작업을 조율하고 WCS가 설비와 명령·상태를 연결합니다. Workspace는 운영 현황과 이력, 운영 환경을 관리하는 화면이며, Studio는 NOVA 또는 기존 시스템의 데이터를 2.5D·3D 현장 배치에 연결합니다. 도입은 현장 진단과 파일럿 정의에서 시작해 운영 검증 결과에 따라 확장합니다.

## 7 작성과 편집 기준

- 한 장에 하나의 설명 목적을 두고, 제목과 도식이 같은 내용을 설명하게 한다.
- 제품 정의 → 역할과 연결 → 같은 작업의 실행·확인·현장 파악 → 운영·확장 → 도입 논의로 이어간다.
- 기능을 나열할 때 고객이 확인하거나 수행하는 업무와 연결한다.
- ‘공통 기능 재사용’만 강조하기보다 표준화와 검증, 현장 맞춤 확장이 주는 가치를 설명한다.
- 기술 용어와 계층 설명은 제품 역할을 이해한 뒤 상세 설명이나 질문 대응에서 사용한다.
- 실제 범위에 맞는 조건과 표현을 유지한다. 근거 없이 단정하거나 모든 현장에 같은 효과를 약속하지 않는다.
- ‘혁신적인’, ‘차세대’, ‘업계 최고’ 같은 수식어 대신 작업·설비·상태·권한·이력의 구체적 역할을 쓴다.
- UI 설명은 원인·상태·다음 행동이 드러나게 쓴다. 예: ‘설비 응답이 없습니다. 전원과 통신 상태를 확인하세요.’
- 버튼은 ‘파일럿 범위 논의하기’처럼 다음 행동을 설명하는 문구로 작성한다.
- 타이포그래피 중심의 가벼운 디자인과 관계가 보이는 도식을 사용한다. 색상·서체·간격·아이콘 규칙은 디자인 기준 문서와 디자인 시스템을 따른다.
