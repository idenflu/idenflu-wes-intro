# NOVA 소개 자료 디자인 기초

## 목적과 적용 범위

NOVA WES/WCS 소개 페이지와 발표 자료를 위한 출발점이다. OpenAI, Apple, 무신사에서 느껴지는 타이포그래피 중심의 정보 위계와 넓은 여백에서 방향을 가져오되 특정 브랜드의 화면이나 자산을 복제하지 않는다. 이 기준은 제품 운영 콘솔 자체의 UI 규격이 아니다.

## 디자인 원칙

1. **타이포그래피 우선**: 한 화면의 핵심 문장을 먼저 정하고, 글자의 크기·무게·행간과 정렬로 읽는 순서를 만든다. 제목은 짧고 구체적으로 작성한다.
2. **여백으로 구분**: 구획을 표시하기 전에 여백과 정렬을 우선 사용한다. 선은 필요할 때만, 카드와 그림자는 관련 정보를 묶는 데 필요한 경우에만 사용한다.
3. **색상은 의미를 위해**: 흰색과 무채색을 기본으로 하고, 브랜드 블루는 링크·강조·선택에 제한적으로 사용한다. 상태 색상은 실제 상태에만 사용한다.
4. **필요한 시각화만**: 제품 화면, 작업 흐름, 구조도는 글만으로 전달하기 어려운 관계나 근거를 설명할 때 사용한다. 장식용 아이콘과 배경 그래픽은 사용하지 않는다. 확인되지 않은 수치나 실화면처럼 보이는 가상 데이터를 성과로 제시하지 않는다.
5. **읽기와 사용성**: 텍스트 대비, 키보드 포커스, 반응형 배치와 모션 축소 설정을 기본으로 고려한다.

## 토큰

실제 값은 `design-system/tokens.css`가 기준이다. 공통 클래스는 `components.css`, 시각 예시는 `design-system/index.html`에서 확인한다.

- **색상**: 배경과 선, 텍스트, 브랜드, 상태 색상을 역할별로 구분한다. `Disabled Text`는 비활성 요소에만 사용하고, 성공·주의·오류는 텍스트와 함께 실제 상태에만 사용한다. 브랜드 기본색 `#266EE1`과 진한 블루 `#0F54BB`는 기존 아이덴플루 디자인 시스템의 Blue 500/600에서 가져왔다. 링크는 기본 잉크색이며 마우스를 올리면 진한 블루를 사용한다.
- **서체**: 기존 아이덴플루 웹사이트와 같은 Pretendard Variable. 로컬 폰트 파일과 라이선스를 함께 포함한다. 사용하지 못할 때 시스템 한글 서체로 대체한다.
- **굵기**: 두 단계로 관리한다. `--nova-weight-regular`(400)은 본문·버튼·라벨·링크·상태, `--nova-weight-medium`(500)은 제목에 사용한다. 굵기를 추가하기 전에 크기와 여백으로 위계를 조정한다.
- **크기**: Display, Heading, Subheading, Item title, Lead, Body, Small, Caption으로 구분한다. Item title은 카드와 목록 제목에 사용하는 20px 크기다. 버튼·상태·Feature 번호는 Small(14px), 배지는 Caption(12px), Feature 본문은 Body(16px)를 사용한다. 텍스트 링크는 주변 글자 크기를 따른다. 큰 제목과 Lead는 화면 크기에 따라 `clamp()`로 조정한다. 타이포그래피 크기는 rem으로 정의하며, px 표기는 브라우저 기본 글자 크기 16px 기준의 환산값이다.
- **간격**: `rem` 토큰으로 관리하며 기본 간격은 0.25rem(4px) 단위다. 세부 간격에는 0.125rem(2px)과 0.375rem(6px)도 사용한다. 섹션 간격은 6–10.5rem, 좌우 여백은 1.25–3rem이며, 콘텐츠 최대 너비는 1200px이다. 괄호 안 px는 브라우저 기본 글자 크기 16px 기준이다.
- **형태와 모션**: 기본 반경 8px, 보조 반경 4px. 버튼과 배지는 완전히 둥근 형태를 사용한다. 모션은 180ms의 짧은 상태 전환에 한정하고 `prefers-reduced-motion`을 존중한다.

## 구성 요소

| 요소 | 용도 | 사용 기준 |
| --- | --- | --- |
| 제목과 본문 | 핵심 메시지와 설명 | 제목은 간결하게, 본문은 약 720px 이내로 유지 |
| 버튼 | 주요·보조 행동 | 기본 높이는 36px이며 테두리 없이 배경색과 글자색으로 위계를 구분한다. 버튼 안의 아이콘은 16px로 표시한다. 아이콘만 있는 버튼은 `nova-button--icon`을 사용하고 접근 가능한 이름을 제공한다. 흰 배경에서는 연한 Control Subtle(`#EFF0F2`)을, Surface 배경에서는 Line 색상을 사용한다. `nova-section--muted`와 `nova-card--filled`에는 자동 적용되며, 다른 Surface 배경에서는 보조 버튼에 `nova-button--on-surface`를 추가한다. 고스트 버튼은 배경 없이 사용하고 마우스를 올리면 은은한 배경을 표시한다. 비활성 버튼은 비활성 전용 텍스트 색상을 사용하며, 고스트 외 버튼에는 연한 회색 배경을 표시한다. 한 영역에 주요 버튼 하나를 우선하고 실제 목적지나 동작을 연결한다 |
| Segmented | 소수의 선택지 중 하나 선택 | 테두리 없이 선택된 항목을 흰 배경과 검정 글자로 구분한다. `segmented.js`를 불러오면 선택 배경이 이동하며, 모션 축소 설정을 존중한다. 그룹 제목과 네이티브 라디오를 사용한다 |
| 텍스트 링크 | 추가 정보 탐색 | 기본은 잉크색과 얇은 밑줄을 사용하고, 링크 텍스트만으로 목적지를 이해할 수 있게 작성 |
| Feature | 가치·특징 나열 | 옅은 상단 선과 작은 번호로 구분하고 3열 이하로 구성 |
| Card | 관련 정보 묶음 | 기본은 테두리 없이 여백으로 구분한다. 필요에 따라 테두리형 `nova-card--outlined` 또는 배경형 `nova-card--filled`를 사용한다 |
| Badge | 제품 영역·분류 | 은은한 배경색과 짧은 텍스트로 표시하고 장식으로 남발하지 않음 |
| Status | 실제 상태 표현 | 작은 색상 점과 정상·주의·오류 등 텍스트를 함께 표시 |
| Comparison | 전후·대안 비교 | 두 항목의 제목과 설명을 같은 위계로 배치하고 동일한 관점의 항목을 짝지어 비교 |
| Steps | 도입 과정·순서 | 순서가 의미 있을 때 번호와 제목을 정렬하고 단계 사이를 여백으로 구분 |
| Table | 여러 항목의 속성 비교 | 제목과 행·열 머리글을 명시하고 머리글에는 Surface 배경을, 행에는 가로 구분선을 사용한다. 좁은 화면에서는 가로 스크롤과 안내 문구를 제공 |
| Details | 용어·역할 목록 | 항목명과 설명을 기준선에 맞추고 모바일에서는 세로로 배치 |
| Icon | 방향·행동·상태 보조 | 기본 20px. 장식보다 의미 전달에 사용하고, 아이콘만 있는 버튼에는 접근 가능한 이름을 제공 |
| Divider | 내용 구분 | 간격만으로 부족한 경우에 사용 |

## 아이콘

`design-system/icons/`에 방향·탐색, 행동, 확인·정보, 운영·콘텐츠 아이콘을 개별 SVG로 제공한다. `05 / ICONS`에서 이름과 모양을 확인할 수 있다. 아이콘은 Lucide 1.62.0을 기준으로 Outline에는 1.5px 선 두께를 적용하고, 일부 아이콘에 `-fill.svg` 변형을 제공한다. Fill은 상태나 선택을 강조할 때 제한적으로 사용한다. 라이선스는 `design-system/icons/LICENSE.txt`에 포함되어 있다.

기본 크기는 20px이며 SVG의 `viewBox`는 24×24다. 텍스트와 함께 쓰는 장식 아이콘은 `<img class="nova-icon" src="design-system/icons/arrow-right.svg" alt="">`처럼 빈 대체 텍스트를 사용한다. 아이콘만 있는 버튼은 버튼에 `aria-label`을 제공한다. SVG를 인라인으로 넣으면 선 색상 `currentColor`가 텍스트 색상을 따른다. `<img>`로 불러올 때는 부모의 텍스트 색상이 SVG에 상속되지 않는다. 마스크를 사용하는 Fill SVG를 같은 문서에 여러 번 인라인으로 넣을 때는 각 SVG의 mask ID와 참조를 고유하게 변경한다.

## 레이아웃과 콘텐츠

- 데스크톱은 최대 1200px 컨테이너, 모바일은 최소 20px 좌우 여백을 사용한다. 700px 이하에서 3열은 1열로 전환한다.
- 소개 흐름은 기존 브리프의 `문제 → 해결 → 구조 → 운영 화면 → 도입 방식`을 따른다. 섹션당 핵심 메시지 하나를 우선한다.
- 각 섹션은 제목과 설명을 먼저 배치한다. 이미지나 다이어그램을 넣기 전에 문장과 여백으로 설명이 충분한지 확인한다.
- 다이어그램은 Platform, Operation, Agent, Orchestration의 책임과 연결을 명확하게 보여준다. 상태색을 구조 분류색으로 혼용하지 않는다.
- 버튼은 실제 이동에는 `<a>`, 동작에는 `<button>`을 사용한다. 상태는 색상에만 의존하지 않는다.
- 제품 화면이나 2.5D 시각 자료는 후속 제작 대상으로 두고, 실제 구현 여부가 불분명한 내용은 예시임을 밝힌다.

## 사용 방법

```html
<link rel="stylesheet" href="design-system/font.css">
<link rel="stylesheet" href="design-system/components.css">
<section class="nova-section">
  <div class="nova-container">
    <span class="nova-eyebrow">NOVA / WES · WCS</span>
    <h2 class="nova-heading">현장을 더 선명하게 봅니다.</h2>
    <p class="nova-lead">작업과 설비, 알림을 하나의 운영 흐름으로 연결합니다.</p>
  </div>
</section>
```

세그먼트 이동 모션을 사용하는 페이지에는 `<script src="design-system/segmented.js" defer></script>`도 추가한다. 스크립트가 없으면 모션 없이 선택 상태를 표시한다.

경로는 HTML 파일 위치에 맞게 조정한다. `components.css`는 토큰을 자동으로 불러오며 기본 `body`, 링크 포커스, 반응형 스타일을 포함한다. 소개 자료 전용 스타일로 사용하고 기존 페이지에 적용할 때는 영향 범위를 확인한다.

## 기준 출처와 후속 작업

- 제품 메시지: 이 저장소의 `docs/nova-intro-brief.md`, `docs/content-design-template.md`
- 브랜드 블루: 인접 `idenflu-design-system`의 색상 토큰. 소개 자료용 중립색·크기·간격은 이 문서의 제안값이다.
- 서체: 인접 `idenflu-website`에서 사용하는 Pretendard Variable 및 동봉 라이선스.
- 후속: 실제 NOVA UI 이미지, 구조도 및 최종 콘텐츠가 확정되면 이 기준으로 소개 자료를 구성하고 검토한다.
